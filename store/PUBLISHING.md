# Публикация NoteInSite в Интернет-магазине Chrome

Всё, что можно было подготовить заранее, лежит в этой папке. Шаги ниже нужно выполнить
самому: они требуют входа в ваш Google-аккаунт, оплаты и принятия соглашения разработчика.

## Что уже готово

| Файл | Назначение |
| --- | --- |
| `../dist/noteinsite-1.1.0.zip` | пакет расширения (39 КБ), `manifest.json` в корне архива |
| `LISTING.md` | готовые тексты всех полей карточки и обоснования разрешений |
| `PRIVACY.md` | текст политики конфиденциальности — его нужно где-то опубликовать и дать ссылку |
| `screenshots/01-notes.png` | скриншот 1280×800: заметки на странице |
| `screenshots/02-editing.png` | скриншот 1280×800: панель редактирования |
| `screenshots/03-popup.png` | скриншот 1280×800: окно расширения |
| `promo-440x280.png` | маленькая промо-плитка (необязательна, но помогает в выдаче) |

Значок 128×128 магазин берёт из самого пакета — отдельно загружать не нужно.

## Шаг 1. Аккаунт разработчика

1. Откройте <https://chrome.google.com/webstore/devconsole> под тем Google-аккаунтом,
   с которого будете публиковать (сменить владельца потом сложно).
2. Примите соглашение разработчика и оплатите разовый регистрационный взнос **5 USD**.
   Без оплаты кнопка публикации недоступна.
3. В «Account» заполните публичное имя разработчика и контактный e-mail, подтвердите e-mail.
   Без подтверждённого адреса товар не отправится на проверку.

## Шаг 2. Опубликуйте политику конфиденциальности

Возьмите текст `PRIVACY.md`, подставьте свой e-mail в разделе «Контакты» и разместите
по постоянному публичному адресу — например, GitHub Pages, публичный Gist, Notion или
страница на вашем сайте. Ссылка понадобится на вкладке Privacy practices.

## Шаг 3. Загрузите пакет

1. В консоли: **Items → Add new item**.
2. Перетащите `dist/noteinsite-1.1.0.zip`.
   Архив уже собран правильно: `manifest.json` в корне, без папок `test/` и `.claude/`,
   пути внутри архива через прямые слэши (магазин не принимает архивы, собранные
   стандартным «Отправить → Сжатая ZIP-папка» из проводника, если внутри обратные слэши).

## Шаг 4. Заполните карточку

Вкладка **Store listing** — тексты и картинки из `LISTING.md`:
название, краткое и подробное описание, категория Productivity, язык «Русский»,
три скриншота из `screenshots/`, промо-плитка `promo-440x280.png`.

Вкладка **Privacy practices** — там же готовые формулировки:
единственное назначение, обоснование `storage`, `contextMenus` и доступа ко всем сайтам,
ответ «удалённый код не используется», ссылка на политику из шага 2 и три обязательных
подтверждения (не продаём, не используем не по назначению, не для кредитных решений).
Сбор данных не отмечайте — расширение ничего не собирает.

Вкладка **Distribution** — регионы и видимость: Public (для всех), Unlisted (только по ссылке)
или Private. Для первой публикации удобно Unlisted, а после проверки переключить на Public.

## Шаг 5. Отправка на проверку

Кнопка **Submit for review**. Сроки:

* обычные расширения — от нескольких часов до 1–3 дней;
* расширения с доступом ко всем сайтам (наш случай) проверяют дольше, иногда до недели.

Статус и возможные замечания приходят на контактный e-mail и видны в консоли.

## Чего ждать от проверки

Наиболее вероятные замечания и ответы на них:

* **«Слишком широкие разрешения»** — в описании и обосновании уже сказано, что заметку
  можно поставить на любом сайте, поэтому перечислить домены невозможно, а содержимое
  страниц не читается. Если проверяющий настаивает, альтернатива — заменить `<all_urls>`
  на `activeTab` + `optional_host_permissions`, чтобы доступ выдавался по клику на иконку.
  Это заметно меняет сценарий (заметки не появятся автоматически при открытии страницы),
  поэтому идти на это стоит только по требованию.
* **«Не совпадает описание и функциональность»** — описание в карточке должно соответствовать
  манифесту; тексты в `LISTING.md` согласованы между собой.
* **Политика конфиденциальности недоступна** — ссылка должна открываться без авторизации.

## Обновление версии

1. Поднимите `"version"` в `manifest.json` (например, `1.0.1`) — магазин не примет
   пакет с тем же номером.
2. Пересоберите архив:

```bash
cd /d/_PROJECT/NoteInSite && python -c "import zipfile,os;files=['manifest.json']+[f'icons/{n}' for n in sorted(os.listdir('icons')) if n.endswith('.png')]+[f'src/{n}' for n in sorted(os.listdir('src'))];z=zipfile.ZipFile('dist/noteinsite-new.zip','w',zipfile.ZIP_DEFLATED);[z.write(f,f) for f in files];z.close();print('ok')"
```

3. В консоли: **Package → Upload new package** → Submit for review.
