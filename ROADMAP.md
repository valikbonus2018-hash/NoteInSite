# Дорожная карта NoteInSite

Составлена 18.09.2026 по итогам разбора кода (`src/`, ~2700 строк), сайта и процесса выпуска.
Порядок этапов — по убыванию отдачи, а не по сложности. Внутри этапа пункты можно брать
в любом порядке, если не указана зависимость.

Обозначения трудоёмкости: **S** — до часа, **M** — половина дня, **L** — день и больше.

## Этап 1. Сохранность данных

Самое неприятное, что может случиться с приложением для заметок, — молча потерять заметку.
Сейчас есть три способа это сделать.

### 1.1. Переполнение хранилища не видно — **S**

`chrome.storage.local` без разрешения `unlimitedStorage` ограничен 10 МБ, а `saveAll()`
(`src/content.js:84`) глушит любую ошибку записи пустым `catch`. При исчерпании квоты
заметка не сохранится, и пользователь узнает об этом, только когда откроет страницу заново.

Добавить `unlimitedStorage` в манифест, показывать тост при неудаче записи, в окне
расширения — предупреждение при подходе к лимиту (`getBytesInUse`).

### 1.2. Две вкладки одной страницы затирают друг друга — **M**

`saveAll()` перезаписывает массив заметок целиком, а `onChanged` во время правки просто
пропускается (`src/content.js:1735`) — изменение из соседней вкладки исчезает при следующем
сохранении. Нужно слияние по `id` + `updatedAt` вместо тотальной перезаписи.

### 1.3. Флаг `selfWrite` — гонка по таймеру — **S**

Флаг снимается через 80 мс (`src/content.js:86`). Запись из окна расширения, попавшая
в это окно, игнорируется; затянувшаяся запись — наоборот, вызывает лишнее перечитывание.
Заменить на метку писателя (идентификатор вкладки + номер ревизии) в сохраняемом объекте.

**Зависит от 1.2** — обе правки трогают один и тот же путь сохранения, делать вместе.

### 1.4. Отмена удаления — **M**

Сейчас ✕ спрашивает подтверждение только у непустой заметки (`src/content.js:1010`),
дальше удаление окончательное. Диалог раздражает, но от промаха не спасает. Сделать
наоборот: удалять сразу, показывать тост «Удалено · Вернуть» на 8 секунд, удалённое
держать в корзине пару дней.

### 1.5. Проверка импортируемого файла — **S**

Импорт (`src/popup.js:290`) сливает в хранилище всё, что подошло под маску ключа, не глядя
на содержимое. Испорченный или чужой файл положит мусор, который потом попадёт в DOM.
Нужна проверка схемы каждой заметки и прогон `html` через `NIS_SANITIZE` на входе.

### 1.6. Напоминание о резервной копии — **S**

Если экспорта не было больше месяца — ненавязчивая строка в окне расширения. До появления
синхронизации (этап 5) это единственная защита от переустановки браузера.

## Этап 2. Производительность и вежливость к чужим страницам

### 2.1. Спящий режим на страницах без заметок — **M**

Сейчас на каждой открытой странице создаётся Shadow-слой, вешается `MutationObserver`
на весь `documentElement` вместе с атрибутами и работает вечный `setInterval` раз в 800 мс
(`src/content.js:1703`). На тяжёлых приложениях — почта, таблицы, карты — постоянная
нагрузка без всякой пользы, потому что заметок там нет.

Если для страницы заметок нет, не должно создаваться ничего: ни слоя, ни наблюдателя,
ни интервала — до первого запроса на создание заметки. Самая заметная оптимизация
и лучший ответ на вопрос «а оно не тормозит?».

### 2.2. Счётчики без полного чтения хранилища — **S**

`updateTotals()` делает `chrome.storage.local.get(null)` — вытягивает всё хранилище ради
двух чисел. При сотнях страниц окно расширения начнёт открываться с задержкой. Держать
счётчики в отдельном ключе-индексе.

### 2.3. Наблюдатель за DOM поточнее — **S**

Подписка на `attributes` по всему поддереву — самая дорогая часть. Сузить до реально
нужного или перевести проверку перекрытия на `IntersectionObserver`.

## Этап 3. Чего не хватает по функциям

### 3.1. Глобальный список заметок с поиском — **L**

Главный функциональный пробел. Окно расширения показывает только заметки текущей страницы;
заметку, оставленную месяц назад, найти нельзя никак — нужно вспомнить страницу и открыть её.

Отдельная страница (`options_page` или `all.html`): все заметки, поиск по тексту,
группировка по сайтам, сортировка по дате, переход к заметке на странице.

### 3.2. Фильтр по цвету — **S**

Цвет заметки уже задаётся, но ни на что не влияет. Фильтрация по цвету в глобальном списке
превращает его в систему меток без новой сущности в интерфейсе. **Зависит от 3.1.**

### 3.3. Текстовый якорь вторым слоем — **L**

`cssPath()` строит точный, но хрупкий путь (`#article > p:nth-of-type(3)`): сайт вставил
блок выше — путь мимо, заметка падает на абсолютные координаты и уезжает.

Сохранять рядом текстовую цитату (30–40 символов до, точный фрагмент, столько же после) —
подход W3C Web Annotation, на котором работает Hypothesis. При провале CSS-пути искать
текст по странице. Переживает перевёрстку, переезд блока и частично редизайн сайта.

## Этап 5. Синхронизация между устройствами — **L**

Данные только локальные: при переустановке Chrome всё держится на том, вспомнил ли
пользователь сделать экспорт. Полноценный `chrome.storage.sync` не подходит — 100 КБ всего
и 8 КБ на ключ.

Два шага:

1. Настройки и список отключённых сайтов — в `sync` сразу, это в лимит укладывается. **S**
2. Заметки — опциональная синхронизация с разбиением по страницам и разрешением конфликтов
   по `updatedAt`. **L**, и только после этапа 1: механика слияния оттуда здесь
   переиспользуется.

## Этап 6. Сайт на HTTPS — **M**

Сайт работает только по http. Это не косметика: Chrome помечает адрес «Не защищено»,
а ZIP, скачанный по http, браузер относит к небезопасным загрузкам и может заблокировать —
то есть основной сценарий установки ломается у части посетителей.

На ho.ua сертификат не выписать: раздела SSL в панели нет, заявка в поддержку отклонена
автоответом (аккаунт на бесплатном тарифе, проверено 17.09.2026).

Перенести статику на Cloudflare Pages или GitHub Pages: бесплатно, HTTPS из коробки, деплой
по push вместо ручной заливки по FTP. ho.ua оставить редиректом. После переноса — поправить
`canonical`, OG-теги и `sitemap.xml`, которые сейчас намеренно указывают http.

Может идти параллельно всему остальному — кода расширения не касается.

## Этап 7. Публикация в Chrome Web Store

### 7.1. Сузить права — **L**

`host_permissions: <all_urls>` плюс content script на всех страницах — это и красная строка
при проверке («читать и изменять все ваши данные на всех сайтах»), и медленное ревью.
Альтернатива — `optional_host_permissions` с выдачей доступа по сайту: пользователь
разрешает конкретный домен при первой заметке. Работы прилично, но это снимает главный
барьер доверия — и в описании магазина, и в будущих отзывах.

### 7.2. Локализация — **M**

Все строки зашиты по-русски прямо в коде. `_locales` + `chrome.i18n` дают украинскую
и английскую версии; без этого карточка находится в поиске магазина только по русским
запросам.

### 7.3. Доступность — **M**

В `src/popup.html` и `src/styles.js` нет ни одного `aria-label` и `role`. Кнопки панели —
голые эмодзи (📌 🌐 – ✕), скринридер прочитает их как символы. Создать и переместить
заметку только с клавиатуры сейчас нельзя.

### 7.4. Мелочи карточки — **S** каждая

* Тёмная тема: `prefers-color-scheme` не используется нигде.
* Печать страницы: поведение заметок в `@media print` не описано — решить, печатаются они
  или прячутся.
* Заметки не работают внутри iframe (`all_frames: false`). Если это осознанно — написать
  в FAQ, иначе будут отзывы «не работает на сайте N».
* Контрольная сумма ZIP на странице загрузки.
